# Discovery 모드 선택

워크스페이스 탐지가 끝났습니다. 기존 `PROTOTYPE-*.md` 명세 파일이 없는 신규(Greenfield)
프로젝트이므로, Discovery를 어디에서 출발할지 선택해야 합니다.

## 두 경로의 차이

| 구분 | Path A — 페인포인트에서 시작 | Path B — 유즈케이스에서 시작 |
|---|---|---|
| 전제 | "삭감 대응이 왜 힘든지"는 알지만, 만들 제품의 형태는 아직 열려 있음 | 후보 제품·기능 아이디어가 이미 여러 개 정리돼 있음 |
| 첫 단계 | Envision — 비즈니스 컨텍스트 + 고객 페인포인트 수집 | Use Case Intake — N개 유즈케이스 상세 수집 |
| 중간 산출물 | PR/FAQ (Working Backwards), 페인포인트 분석 | 프레임워크 기반 점수·순위표 |
| 이후 | Solution Analysis에서 해결책이 1개인지 여러 개인지 판단 (여러 개면 Path B와 합류) | 상위 3개 선정 → PROTOTYPE-*.md 생성 |
| 어울리는 상황 | 문제 정의부터 제품 후보 도출까지 함께 하고 싶을 때 | 이미 있는 후보들 중 무엇을 먼저 만들지 정하고 싶을 때 |

요청하신 내용("보험 심사청구팀의 삭감 대응 업무를 개선하는 제품을 찾고 싶다")은 해결할 **문제 영역**은
정해져 있지만 **제품 후보**는 아직 열려 있는 상태로 읽힙니다. 이 경우 일반적으로 Path A가 맞습니다.
다만 팀 내부에 이미 검토 중인 후보 목록(예: 삭감 사유 자동 분류, 이의신청서 초안 생성, 삭감 예측 등)이
정리돼 있다면 Path B로 바로 우선순위화에 들어가는 편이 빠릅니다.
