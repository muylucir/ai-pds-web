# PROTOTYPE-qa-testcase-copilot

> **공유용 프로토타입 사양서** — 이 파일은 개발/워크숍 팀에 그대로 전달할 수 있습니다.
> 상태: 초안 (일부 "입력 필요" 항목은 PM이 제공 예정).

## 1. 개요
**이름(가칭)**: QA TestCase Copilot
**한 줄 설명**: 흩어진 정책/기획 문서를 분석해 고품질 TC 초안과 확인 문의사항을 만들고, 명세화된 기준으로 각 TC를 Auto / Manual / 휴먼체크로 근거와 함께 분류하는 Claude(AWS Bedrock) 기반 웹 도구.

**주 사용자**: QA 엔지니어 (테스트 설계·실행·자동화 담당)

**해결 문제**:
1. 정책/기획서가 Figma·Confluence·기획서에 흩어져 있어 TC 설계에 시간·휴먼에러가 크다.
2. TC Auto/Manual 판별이 주관적이라 일관성이 낮고, 구현 단계 오분류로 재작업이 발생한다.

## 2. 핵심 파이프라인
```
+---------------------------+     +----------------------------+     +-----------------------------+
| 입력                       | --> | 1) 정책 분석 & TC 초안 생성   | --> | 2) Auto/Manual/휴먼체크 분류  |
| - 정책/기획 텍스트 붙여넣기  |     |    + 확인 문의사항 도출      |     |    (기준 적용 + 근거 기록)     |
| - 기존 TC 시트 업로드(분류만) |     |                            |     |                             |
+---------------------------+     +----------------------------+     +-----------------------------+
                                                                              |
                                                                              v
                                                                   +-----------------------------+
                                                                   | 출력: 팀 TC 포맷 표          |
                                                                   | + 문의사항 목록 + 분류 근거   |
                                                                   +-----------------------------+
```

두 개의 진입점:
- **진입점 A (생성→분류)**: 정책 텍스트 입력 → TC 생성 → 분류까지 전체 파이프라인.
- **진입점 B (분류만)**: 기존 TC 시트 업로드 → 각 TC를 Auto/Manual/휴먼체크로 분류.

## 3. 입력 (Inputs)
- **정책/기획 텍스트 붙여넣기** (초기 검증에 우선): 자유 텍스트 입력.
- **기존 TC 시트 업로드**: CSV/XLSX. 컬럼 매핑 UI로 시나리오/기대결과 등 인식.
- (후속 확장) Confluence 링크, Figma 정책 연동.

## 4. 출력 (Output)
- **TC 표** — 팀 고유 포맷 적용.
  - [입력 필요] 팀 고유 TC 포맷/컬럼 정의를 제공받아 확정. 기본값(제공 전까지):
    `TC ID | 시나리오 | 사전조건 | 스텝 | 기대결과 | 우선순위 | 분류(Auto/Manual/휴먼체크) | 분류근거 | 문의사항`
- **문의사항 목록** — 정책에 없거나 모호해 확인이 필요한 항목(임의 추정 금지).
- **분류 근거** — 각 TC가 왜 그 분류로 판단됐는지 기준 항목과 매핑.
- 내보내기: CSV/XLSX (팀 포맷).

## 5. 분류 로직 (Auto / Manual / 휴먼체크)
- [입력 필요] **명세화된 분류 기준 문서**를 제공받아 프롬프트로 인코딩.
- 기본 기준 축(제공 전까지): 사전조건 의존도, 테스트 데이터 준비 필요, CMS 사전 설정 필요, UI 변동성, 결과 검증의 결정성.
- **규칙**: 기준에 명확히 부합하지 않거나 애매한 케이스는 임의로 Auto 처리하지 않고 **휴먼체크**로 분류하고 사유 기록.

## 6. 프론트엔드
- **웹 앱 (데스크톱 브라우저)**.
- 화면 구성:
  1. 입력 화면: 정책 텍스트 붙여넣기 / TC 시트 업로드 탭.
  2. 처리 상태 화면.
  3. 결과 화면: TC 표(편집 가능) + 문의사항 패널 + 분류 근거 토글 + 내보내기 버튼.

## 7. LLM / 기술 구성
- **제공자**: AWS Bedrock (Claude)
- **모델 ID**: `us.anthropic.claude-sonnet-4-20250514-v1:0` (교차 리전 추론 프로파일 사용 — 직접 모델 ID 사용 금지)
- **리전**: 예) `us-west-2`
- **인증 (택1)**:
  - 개발: `AWS_BEARER_TOKEN_BEDROCK` (환경변수)
  - 운영: `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY` + `AWS_REGION`
- 주의: Bedrock 콘솔에서 Claude Sonnet 4 모델 액세스 활성화 필요.

## 8. 프롬프트 설계 개요
- **분석 단계**: 정책 텍스트에서 테스트 관점(정상/경계/예외/권한/데이터 조건)을 구조화. 누락·모호 지점은 "문의사항"으로 분리.
- **생성 단계**: 팀 TC 포맷에 맞춰 초안 생성. 각 TC에 검증 가능한 기대결과 명시(불명확 시 "확인 필요"로 문의사항 연결).
- **분류 단계**: 제공된 기준에 따라 Auto/Manual/휴먼체크 부여 + 근거. 애매 시 휴먼체크.

## 9. 비목표 (Non-goals, 초기)
- API 명세 분석/검증, DB 컬럼 매칭, 자동화 로케이터 자가 치유, 회귀 세트 생성, 실패 분석 LLM 보강, Slack 요약/알림 — 후속 후보.

## 10. 성공 지표 (제안)
- TC 초안 작성 시간 단축률
- 담당자 간 Auto/Manual 분류 일치율
- 구현 단계 Manual 재분류(재작업) 발생 감소율
- AI 초안의 수기 보완 비율 감소

- [ ] (선택) 샘플 정책 텍스트 1건 + 해당 정답 TC 예시 (품질 검증용)
