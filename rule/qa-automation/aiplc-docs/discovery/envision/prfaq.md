## PRESS RELEASE

### 헤드라인
**"QA TestCase Copilot 출시 — 흩어진 정책 문서에서 고품질 테스트 케이스를 자동 설계하고, 자동화 가능 여부를 일관된 기준으로 분류합니다."**

### 부제
QA 엔지니어가 Figma·Confluence·기획서를 일일이 뒤지지 않아도, AI가 정책을 분석해 TC 초안과 확인 질문(문의사항)을 만들고, 각 TC를 Auto / Manual / 휴먼체크로 근거와 함께 분류합니다.

### 요약 (Summary)
오늘, QA 팀을 위한 **QA TestCase Copilot**을 공개합니다. Claude 기반의 이 도구는 여러 곳에 흩어진 기획·정책 문서(Figma, Confluence, 기획서)를 읽어 테스트 관점을 누락 없이 도출하고, 검토 가능한 TC 초안과 "정책에 명시되지 않아 확인이 필요한 문의사항"을 함께 제시합니다. 또한 명세화된 판별 기준(사전조건 의존, 데이터 준비 필요, UI 변동성 등)에 따라 각 TC를 Auto/Manual/휴먼체크로 분류하고 그 근거를 남깁니다. QA 엔지니어는 처음부터 작성하는 대신 "검토·보완"에 집중해, TC 설계 시간을 크게 줄이고 담당자 간 편차 없는 일관된 품질을 확보합니다.

### 문제 (The Problem)
QA 엔지니어의 TC 설계는 두 가지 병목에 묶여 있습니다.
1. **정책이 흩어져 있다.** 기획·디자인 정책이 Figma와 Confluence 여러 문서에 분산돼 있어, 일일이 확인하고 히스토리를 추적하는 데 시간이 과도하게 들고 휴먼 에러가 발생합니다. AI로 초안을 뽑아도 품질이 낮아 수기 보완이 반복됩니다.
2. **자동화 판별이 주관적이다.** TC를 Auto/Manual로 나누는 기준이 담당자 경험에 의존해 사람마다 결과가 다르고, 구현 단계에서 Manual임을 뒤늦게 발견해 작업 리소스를 낭비합니다.

### 해결책 (The Solution)
QA TestCase Copilot은 세 가지를 제공합니다.
1. **정책 인제스트 & 컨텍스트화** — 지정한 정책 문서 출처(Figma/Confluence/기획서)를 읽어 테스트 관점을 구조화하고, 출처 링크를 함께 표기해 히스토리 추적을 돕습니다.
2. **고품질 TC 초안 + 문의사항 도출** — 검토 가능한 TC 초안을 생성하고, 정책에 명시되지 않았거나 모호한 부분은 "확인 필요 문의사항"으로 분리해 QA가 놓치지 않게 합니다.
3. **일관된 Auto/Manual/휴먼체크 분류** — 프롬프트로 명세화된 판별 기준을 적용해 각 TC를 분류하고, 애매한 케이스는 임의 Auto 처리 대신 '휴먼체크'로 보내며 판단 근거를 남깁니다.

### 고객 관점 인용 (Customer Quote)
> "예전엔 정책 문서를 다섯 군데 열어놓고 하루 종일 TC를 짰는데, 이제는 Copilot이 만든 초안과 확인 질문을 검토·보완만 하면 됩니다. 무엇보다 자동화 여부 분류가 사람마다 다르던 문제가 사라졌어요." — QA 엔지니어

### 리더 관점 인용 (Leadership Quote)
> "판별 기준이 프롬프트로 문서화되면서 팀 전체가 같은 기준으로 판단합니다. TC 품질 편차와 구현 단계 재작업이 눈에 띄게 줄었습니다." — QA 리드

### 사용 방법 (How to Get Started)
1. 정책/기획 문서 출처를 지정한다 (Figma/Confluence 링크, 기획서 파일).
2. Copilot이 문서를 분석해 TC 초안 + 문의사항 목록을 생성한다.
3. QA가 문의사항을 확인/보완하고, Copilot이 각 TC를 Auto/Manual/휴먼체크로 분류한다.
4. QA는 근거를 검토해 확정하고, 자동화 대상만 구현 단계로 넘긴다.

### Call to Action
QA 팀이라면 지금 대표 기능 하나(정책 기반 TC 초안 생성, 또는 Auto/Manual 분류)부터 프로토타입으로 검증해 보세요.

## FAQ

### 고객 FAQ

**Q. 어떤 문서를 입력으로 받나요?**
A. 초기에는 Confluence 페이지, Figma 정책, 기획서(텍스트/문서)를 대상으로 합니다. 문서 출처 링크를 함께 표기해 히스토리 추적을 지원합니다.

**Q. AI가 만든 TC를 그대로 써도 되나요?**
A. 아니요. Copilot은 "검토 가능한 초안"과 "확인이 필요한 문의사항"을 분리해 제시합니다. QA의 검토·확정을 전제로 설계되어, 애매한 부분을 자동으로 단정하지 않습니다.

**Q. Auto/Manual 분류 기준은 무엇인가요?**
A. 사전조건 의존, 테스트 데이터 준비 필요, CMS 사전 설정 필요, UI 변동성 등 명세화된 기준을 프롬프트로 적용합니다. 기준에 맞지 않거나 애매하면 '휴먼체크'로 분류하고 근거를 남깁니다.

**Q. 정책이 문서에 없거나 모호하면 어떻게 되나요?**
A. 임의로 추정하지 않고 "확인 필요 문의사항"으로 도출해, QA가 기획/개발에 질의할 수 있게 합니다.

### 내부 FAQ (Internal)

**Q. 왜 지금인가?**
A. 팀이 이미 Claude/Claude Code를 사용 중이고, TC 설계·분류가 반복적·규칙화 가능한 영역이라 AI 적용 효과가 크고 즉시 적용 가능합니다.

**Q. 성공 지표는?**
A. (제안) ① TC 초안 작성 시간 단축률, ② 담당자 간 Auto/Manual 분류 일치율, ③ 구현 단계 Manual 재분류(재작업) 발생 감소율, ④ AI 초안의 수기 보완 비율 감소.

**Q. 가장 큰 리스크는?**
A. 정책 문서의 품질/접근성 편차와 컨텍스트 비용. 초기에는 대상 문서 범위를 좁혀 품질을 확보하고 점진 확장합니다.

**Q. 범위 밖(향후 확장) 항목은?**
A. API 명세 분석/검증, DB 컬럼 매칭, 자동화 로케이터 자가 치유, 회귀 세트 생성, 실패 분석 LLM 보강, Slack 요약/알림 등은 후속 후보로 둡니다.

**Q. 단일 솔루션인가, 복수 솔루션인가?**
A. 초점은 두 축(정책 기반 TC 설계 / Auto·Manual 분류)입니다. 다음 단계(Solution Analysis)에서 단일 통합 도구로 갈지, 두 개의 분리된 솔루션으로 갈지 결정합니다.
